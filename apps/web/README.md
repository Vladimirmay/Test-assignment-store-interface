# @checkout/web

Фронтенд магазина: React 18 + TypeScript + Vite, React Router, TanStack Query.

## Запуск

Из корня репозитория (нужен уже поднятый API, см. корневой [README](../../README.md)):

```sh
npm ci
npm run dev -w @checkout/web
```

Откроется на [http://localhost:5173](http://localhost:5173) и обратится к API на `http://127.0.0.1:4000` (переопределяется переменной `VITE_API_BASE_URL`).

Сборка и предпросмотр:

```sh
npm run build -w @checkout/web
npm run preview -w @checkout/web
```

## Устройство

- `src/api/client.ts` — единственное место, которое делает `fetch`: базовый адрес, заголовки, `Idempotency-Key`, разбор `data`/ошибки. Компоненты получают типизированные данные или уже нормализованную ошибку (`RequestError`), но никогда сырой `Response`.
- `src/api/endpoints.ts` — типизированные функции по одной на ресурс API, поверх `client.ts`. Типы данных берутся из `@checkout/contracts`, кроме тех, что пакет не экспортирует как TS-тип (например, `Session`) — они описаны в `src/api/types.ts`.
- `src/queries/*` — обёртки над TanStack Query: кэш, инвалидация после мутаций (`useSetCartItem`, `useRemoveCartItem`), в дальнейшем — поллинг статуса оплаты/заказа через `refetchInterval`, который React Query сам останавливает после ухода со страницы.
- `src/session/SessionProvider.tsx` — создаёт гостевую сессию при первом заходе и хранит токен в `localStorage`.
- `src/ui/*` — общие компоненты состояний (`Loading`, `ErrorBanner`), чтобы загрузка/ошибка не описывались заново в каждой странице.

## Статус

Готово: каталог (загрузка, недоступный товар), корзина (изменение количества, удаление, итог с сервера).

В разработке: оформление заказа (контакты, доставка, расчёт), оплата тестовой картой/наличными, страница статуса заказа с восстановлением после перезагрузки.
